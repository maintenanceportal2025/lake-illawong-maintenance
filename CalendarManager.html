📋 Calendar Manager — Admin Reference

⛔ Block Time

Pre-fills the Book tab with a full-day placeholder (8:00 AM – 10:00 PM, titled "BLOCKED: Maintenance/Cleaning") for the selected facility. Review and adjust the date/time/title before clicking Create Booking — it doesn't create anything on its own, it's a convenience starting point, same as any other booking once created.

⚠️ Double-Booking Prevention

The backend rejects any create or edit that overlaps an existing active booking for that facility — this is enforced server-side (FacilitiesBooking backend V1.6+), not just a warning. Check Availability on the Book tab is a preview of that same check; you don't need to run it separately before creating, but it can save a round trip if you suspect a clash.

Editing a booking's own time

Won't falsely conflict with itself — the backend excludes the booking being edited from its own conflict check.

👤 Roles

Access requires the Calendar-Manager or Developer roleTag, verified via OTP. Calendar-Manager is a standalone role — assign it to anyone who needs to manage facility bookings; it doesn't carry any Board/Admin access on its own.

🚫 Cancel vs. Delete

Cancelling a booking marks it Cancelled and removes it from the facility calendar, but keeps the record for audit purposes — it stays visible under the "Cancelled" filter on Manage Bookings. There's no permanent delete function; this matches how records are retained elsewhere in the system.

📅 Recurring Bookings

Not yet available. Each booking (including Block Time) is a single, one-off event — a recurring booking feature is a tracked future enhancement, deliberately scoped as its own piece of work rather than added ad-hoc.
